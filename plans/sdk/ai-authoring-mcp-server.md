# SDK spec — AI authoring MCP server

- **Origin:** pegasus-workflows repo (`~/repos/pegasus-workflows`), `sdk-feedback/0001-ai-authoring-mcp-server.md`
- **Status:** Shipped
- **Filed:** 2026-06-25
- **SDK version when filed:** 0.1.1
- **SDK version that addresses it:** 0.2.0
- **Area:** tooling / CLI / docs

## Problem

A developer authoring Pegasus workflows with an AI coding agent has no
structured way to give the agent the SDK's context and capabilities. Today the
agent must infer the rules by reading installed package source: the manifest
schema, the three-shape input contract, the workflow/activity determinism
boundary, and the `PegasusClient` surface. That inference is slow, drifts as the
SDK changes, and is wrong often enough to produce workflows that fail validation
(e.g. registering under the class name instead of the manifest name, or calling
`PegasusClient` from workflow code where `httpx` is sandboxed).

We want the SDK itself to ship the context and the safe actions an agent needs,
so any agent — not just Claude Code — gets them with one config line.

## Why it matters

- **Correctness:** the SDK already encodes the rules (`manifest.validate_manifest_fields`,
  `package_project`, `PegasusClient`). An agent reaching those directly can't
  drift from real behavior; an agent guessing from prose can and does.
- **Reach:** workflow authors use varied agents (Claude Code, Cursor, Windsurf).
  A provider-neutral surface serves all of them; a Claude-only artifact doesn't.
- **Adoption:** "point your agent at `pegasus-workflows mcp`" is a far lower bar
  than asking each team to hand-maintain agent context per editor.

## Proposed change

Ship an **MCP server as a subcommand of the existing Typer CLI**:

```bash
pegasus-workflows mcp            # stdio MCP server (default transport)
```

Add `mcp` as an **optional extra** so the base SDK stays lean:

```bash
pip install 'pegasus-workflows-sdk[mcp]'
```

`pegasus-workflows mcp` with the extra uninstalled should exit non-zero with a
clear "install the `mcp` extra" message.

The server is a thin shell over existing SDK internals — it must not
reimplement validation, packaging, or API logic.

### MCP resources (context — read-only)

- `pegasus://guide/authoring` — the authoring guide (import surface,
  determinism rule, input contract).
- `pegasus://guide/input-contract` — the three input shapes, worked example.
- `pegasus://reference/manifest` — manifest fields + regexes, generated from
  `manifest.py` constants so it can't go stale.
- `pegasus://reference/api` — the `PegasusClient` method surface (names,
  signatures, docstrings), generated by introspection.

### MCP tools (safe actions)

- `scaffold_workflow(name, dest)` → wraps `cli.init.render_project`; returns the
  created file tree. (Local, no network.)
- `validate_manifest(path|toml_text)` → wraps `manifest.load_manifest` /
  `validate_manifest_fields`; returns structured errors or the parsed manifest.
- `package_project(project_dir)` → wraps `package.package_project`; returns the
  `(name, version, zip_path, bytes)` results.
- `validate_integration_config(integration_id, mapping, rules, corpus, base_url, token)`
  → wraps `PegasusClient.validate_integration_config` (dry-run gate, no write).

Network-mutating actions (`push`, `publish_integration_config`, `run`) are
**out of scope** for the MCP server — keep those human-gated via the CLI.

### Docs

README section: "Using the SDK with an AI coding agent," with copy-paste MCP
config for at least Claude Code and one other agent, plus a one-line
description of each resource/tool.

## Acceptance criteria

- [ ] `pip install 'pegasus-workflows-sdk[mcp]'` installs an MCP dependency; the
      base `pip install pegasus-workflows-sdk` does **not** pull it in.
- [ ] `pegasus-workflows mcp` starts a stdio MCP server that completes an
      `initialize` handshake and lists capabilities.
- [ ] Without the extra, `pegasus-workflows mcp` exits non-zero with a message
      naming the `mcp` extra.
- [ ] Resources `pegasus://reference/manifest` and `pegasus://reference/api` are
      generated from `manifest.py` / `PegasusClient` (verified: changing a
      constant or method docstring changes the served resource — no hardcoded
      copy).
- [ ] `validate_manifest` tool rejects a bad name (e.g. `"Bad Name"`) with the
      same error text as `validate_manifest_fields`, and accepts a scaffolded
      project's `pegasus-workflows.toml`.
- [ ] `scaffold_workflow` tool produces the same tree as
      `pegasus-workflows init` for the same name.
- [ ] `package_project` tool returns a zip path that exists and matches the CLI's
      output for the scaffolded project.
- [ ] No mutating/network-publishing tool (`push`, `publish_*`, `run`) is exposed.
- [ ] README documents agent setup with working config for ≥2 agents.

# Store listing assets

Everything the App Store and Google Play listings need, and the scripts that
regenerate it. All of it is **generated** — edit the inputs, re-run a script,
never hand-edit an output PNG.

## Inputs (the only things you edit)

| File                                 | What it is                                                                                                   |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `../assets/logo-source.svg`          | The **square logo mark**. Source of truth for every icon. SVG, or PNG ≥1024px with a transparent background. |
| `../assets/logo-wordmark-source.svg` | Optional horizontal lockup (mark + wordmark). Used by the login screen and the feature graphic.              |
| `brand.json`                         | App name, subtitle, tagline, palette, and the scale each icon variant uses.                                  |
| `fixtures/screens.json`              | **Every value that can appear in a screenshot.** Review this to audit the listing.                           |
| `listing/listing-copy.md`            | Store descriptions, keywords, and the review notes Apple requires.                                           |

## Scripts

Run from `apps/mobile/`.

| Command                 | Does                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------- |
| `npm run store:icons`   | Derives every launcher + store icon from the logo source, and verifies the store rules. |
| `npm run store:export`  | Builds the web bundle the capture drives. Re-run after **any** app code change.         |
| `npm run store:capture` | Drives that build in Chromium and writes raw screenshots at exact store sizes.          |
| `npm run store:compose` | Wraps the raw captures in branded panels and renders the Play feature graphic.          |

Full refresh:

```
npm run store:icons && npm run store:export && npm run store:capture && npm run store:compose
```

## Outputs

```
ios/
  icon-1024.png                 App Store Connect marketing icon (no alpha channel)
  screenshots/raw/*.png         1320x2868 — the 6.9" iPhone set ASC requires
  screenshots/framed/*.png      same size, on a branded panel with a caption
android/
  icon-512.png                  Play listing icon, opaque
  feature-graphic.png           1024x500 — required for a Play listing
  screenshots/raw/*.png         1080x2400
  screenshots/framed/*.png      same size, branded
```

`../assets/{icon,adaptive-icon,splash-icon,favicon}.png` are also regenerated by
`store:icons` — those are the app's own assets, not listing ones. So are the two
in-app logo variants:

- `logo-mark.png` — the mark in its own `#285785`, for **light** grounds.
- `logo-mark-light.png` — reversed to white, for **dark** grounds. The login
  screen (`colors.backgroundDark`) and the Play feature graphic both use this
  one; the colour mark on `#0F172A` measures 2.37:1 and disappears.

### The icon ground is a two-place setting

`brand.json` → `colors.iconBackground` is `#F8FAFC`, and `app.json`'s
`splash.backgroundColor` **and** `android.adaptiveIcon.backgroundColor` must
match it. Nothing enforces that automatically — change one, change all three.
The mark is a mid-blue drawn for light backgrounds (7.19:1 on slate-50, 2.37:1
on the navy that was there before), and it is 1.44:1 wide, so it fills a square
tile by width and carries deliberate space above and below.

**Upload raw or framed?** Both stores accept either. Raw is the safer default
for a first submission: it is unambiguously "the app", which is what a reviewer
is checking. Framed reads better in a crowded search result. Pick per listing;
both are generated.

## How the screenshots are made

`store:capture` drives the **real app** — `expo export --platform web` builds
the actual `app/` routes through react-native-web and Playwright walks them. No
screen is re-implemented here, so a UI change shows up in the next capture
instead of drifting from a mockup.

The API is served from `fixtures/screens.json`, not a live backend, because:

- no real customer name or address can reach a public listing,
- captures are reproducible months later, on any machine,
- no prod credentials, VPN tunnel or CORS proxy is needed to re-run it.

The auth wall is passed the way the app itself passes it on web: by seeding
`localStorage['pegasus_session']`, exactly what `src/utils/storage.ts` writes
after a real login.

### Three things that will bite you

1. **Screens are reached by tapping, not by URL.** `app/_layout.tsx` wraps them
   in `<Stack.Protected guard={isAuthenticated}>`, and that guard is false for
   the first frames while the session is restored from storage — so every deep
   link bounces to `(auth)` and lands on the dashboard. Add new screens to the
   `SCREENS` flow with a `tapText`/`tapLabel`, not a path.

2. **`store:export` sets `PEGASUS_STORE_CAPTURE=1`**, which makes
   `metro.config.js` swap `react-native-document-scanner-plugin` for a web stub.
   The real module calls `TurboModuleRegistry.getEnforcing` at module scope with
   no web implementation; without the stub it throws on import and blanks the
   entire shipment route. Device and store builds are unaffected — the alias is
   gated on both `platform === 'web'` and that env var.

3. **One react-native-web layout defect is patched at capture time.** RNW gives
   the trips filter-chip ScrollView a stale explicit height, which
   `align-items: stretch` pushes down until each pill is shorter than its own
   text. Native lays the same screen out correctly, so the fixup restores
   fidelity rather than inventing it. It asserts its own result, so if a future
   RNW release changes this the capture fails loudly instead of shipping a
   squashed PNG. See `relaxCollapsedChipRow` in `scripts/capture-screens.mjs`.

## Store rules the icon script enforces

- **Apple**: the 1024 marketing icon must carry **no alpha channel** — fully
  opaque is not sufficient, the channel itself has to be absent.
- **Play**: the 512 listing icon may have an alpha channel but nothing may be
  transparent; Play composites its own shape mask and renders transparency as
  black.
- **Android adaptive foreground**: must _keep_ its alpha, and the mark must stay
  inside the circular-mask safe zone (`brand.adaptiveScale`). Android crops the
  outer ~1/6 on every side.
